# AMD gfx1100 (RDNA3) HIP port — fork status

> This fork of [Niko1221/Strata](https://github.com/Niko1221/Strata) carries the working HIP port for
> RDNA3 (gfx1100 — Radeon RX 7900 XT/XTX/GRE class). Upstream now ships a HIP backend with an RDNA4
> (gfx1201) lead; this fork maintains the gfx1100 lineage — the patch-table pipeline, the verified
> kernel suite and the measured 7900 XTX work — with pieces proposed upstream one concern per PR.
> Port thread with findings: [Niko1221/Strata#106](https://github.com/Niko1221/Strata/issues/106).
>
> **How this was made:** the port, its verification campaigns and this document were produced by an
> AI engineering agent powered by **GLM-5.3 (Z.ai)** working under
> [xyzzing](https://github.com/xyzzing)'s direction — every number below traces to a recorded
> measurement on this machine. The measured model is **Qwen3.8-Flash-Next** (Qwen team; ISTA-DASLab
> GSQ-RCO IQ3_S compression), served as this machine's local resident (loopback 8081) with its MTP
> draft layer as the speculative-decoding drafter in every decode figure. Full credits at the end.

## What is verified (parity-first)

Every kernel on the default forward path is tested on the card against independent references
before any performance claim is made:

- Kernel suite on gfx1100 — last recorded full runs: **0.1.31: 42 passed / 0 failed / 2 declared
  weight-gated skips; 0.1.33: 53 passed; 0.1.35: 55 passed; 0.1.40 line (refresh-0140, 2026-10-06):
  86/87 passed + 2 declared skips** (the historically documented `hipblaslt_gemm`/`hcd_exact` class)
  **+ 1 upstream-declared CUDA-only-by-design failure** — the first full-suite run on a 0.1.40 base,
  including **upstream's own `hip_prompt_attn_wmma` parity passing on gfx1100** and the Aurora
  gfx11 fused-expert tests. All ten IQ quantization formats bit-exact on the new line too.
- **All ten IQ quantization formats bit-exact** against gguf-py (a second, independent
  implementation in another language); MMQ prefill **8/8** types verified on the card, IQ3_S (the
  model's weight format) included.
- The discipline found and fixed two real forward-path defects (an 80 KB dynamic-LDS overrun and an
  FMA-contract divergence), and records a HIP `__vsub4` saturation divergence vs CUDA for any
  IQ-format mismatch.

### The 0.1.40 line on this card (2026-10-06 paired engine-vs-engine)

Upstream 0.1.40 ships its own gfx11 arms under the same opt-in keys this fork proposed (select
scorer `92dde2f` in **bf16**, prompt attention in fp16, a fused-native arm, and the absorbed
100500 table). Paired A/B against this fork's production line (identical args/env incl. the same
table; 5 pairs × arms alternating per tier, one-shot greedy, engine versions stamped per cell —
`0.1.39-65a3c8f` vs `0.1.40-d8d3529`; `ab-refresh0140-20261006.json` + `-deep-`):

| comparison (b = 0.1.40 + upstream arms, a = 0.1.39 + our fp16 arms) | result |
| --- | --- |
| decode, 1K tier (the #1008 regression check) | **no regression** — 67.1 → 69.5 tok/s median, paired +2.5% (n=5) |
| prefill @128K, paired | **−2.27% for 0.1.40** (4/5 pairs in 0.977–0.981) |
| prefill @32K, paired | −1.26% |
| decode, 32K/128K tiers | +4.7% / −1.2% (small, mixed) |
| **`qsa select` phase @128K** | **1934 ms (3.2%) ours vs 3176 ms (5.1%) upstream's — fp16 is 1.64× faster than bf16 here** |
| `qsa attn` phase @128K | 9.8% vs 9.6% — the prompt-attention arms are equivalent on this card |

Every other prefill phase is within 0.4%: the select operand class is the entire 0.1.40 delta.
Our 1934 ms reproduces the 1952 ms recorded when the fp16 kernel first landed (2026-10-05), and
the comparison was posted upstream on the shipped arm's thread ([PR #944,
comment 6016189613](https://github.com/Niko1221/Strata/pull/944#issuecomment-6016189613)) with a
re-file offer. Swap decision open: stay on 0.1.39 / 0.1.40 as-is / re-land the fp16 select arm on
`refresh-0140` then swap (the data favors the third).

**Desktop-load context (matters for absolute numbers):** today's quiet-desktop cells read
**2148–2153 tok/s @128K prefill on the production line — +15% over the recorded 1863** measured
2026-10-04 with the desktop under browser load. Desktop memory pressure costs double-digit
prefill on this DRAM-bound engine; paired verdicts are unaffected (same conditions both arms),
but absolute numbers across days must name the desktop state.

## Measured and rejected (records kept)

Everything on the decode critical path has been measured; what did not win is recorded, not
deleted: `--spec-split` (retracted — it *costs* ~27% decode), `--prefill 8192` (0.0%), the
`--pcie-frac` sweep, pool `MT_MULT`, ring-wait pipelining (−0.94%), learned expert placement
(−1.53% on-distribution; conditional on a workload shift), `STRATA_MTP_BATCH_F16`,
`STRATA_VERIFY_DEVICE_PLAN`, the rocWMMA full-scorer (parity-clean but ~2× slower than portable),
and 24 GB full-expert-residency (arithmetically impossible: the smallest whole-pack quant is
63.35 GiB). Two more from the 2026-10-05/06 campaigns, kept for the records: the fused-int8 MoE
kernels (above — engagement REJECT at parity on gfx1100), and the **INT8-Q score path**
(rocWMMA int8→i32, integer-exact vs double at 4.9e-8, but the pre-declared precision gates fail
on the quantization class — softmax weight delta 9.5e-2 vs the 2e-2 bound under the 12×-outlier
activation class; the fp16 hi/lo incumbent is ~2⁻²². Structural, not tunable: fixture
`tests/hip/qsa_int8_q_fixture.cu`, verdict in `65a3c8f`'s message).

## Limits and open work

- **Context above 128K is now measured** (2026-10-05 ladder, native 262,144 model + YaRN,
  `--kv-resident` streaming keeps VRAM flat at 23.1 GiB): needle recall is CORRECT at 262K and
  512K depth 50% (523,776 prompt tokens found), prefill 1901 tok/s @262K / 1536 @512K — but the
  512K tier REJECTs on the decode gate (28.0 vs the 37.1 floor): MTP draft acceptance collapses
  0.803 → 0.056 at depth. The missing piece is a depth-capable drafter — a model/training lever,
  not an engine knob. 256K is the viable class today.
- **No same-weights logit reference exists** here (a second ~84 GB-resident reference cannot
  coexist in 96 GB RAM) — the correctness claim rests on the per-kernel parity suites, not on
  end-to-end logits.
- The QSA scorer's portable path is deliberately reference-speed; the tensor-core arms above are
  the opt-in fast paths. The remaining ~10% attention share is quantization-gated (see the INT8-Q
  verdict above), not MMA-throughput-gated.
- Upstream PR state (2026-10-06 sweep, gh-verified): **#755 merged for 0.1.40** (the table,
  byte-identical, authorship kept); **#786 superseded with credit** (0.1.40 ships its own gfx11
  prompt-attention arm; "your kernel and layout work was the starting point"); **#744, #319, #745,
  #888, #999 auto-closed by upstream's history rewrite** — explicitly "not a rejection", with a
  re-file recipe; **#944** (the third-party gfx11 arms PR upstream absorbed) carries our
  fp16-vs-bf16 select comparison + re-file offer. Merged earlier: Monitor rate fix #104. The
  engine binary prints its own tree state (`0.1.39-<git-describe>`, `0.1.40-<git-describe>`); the
  fork's CI runs CPU tests plus HIP/CUDA compile jobs on every push (the CUDA job's known gap is
  the WY kernel's 50.4 KB static LDS over nvcc's 48 KB static limit — a dynamic-smem port is
  queued, parity-gated).
