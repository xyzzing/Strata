## Nightly decision

**No second nightly is installed.** Grounds:
1. The current stack is already a 10.2.0 TheRock nightly; the delta to another daily is unquantified
   and the audit found no compiler-shaped symptom in the measured data (the one gap, V01's
   projection efficiency, is a load/occupancy question first).
2. Hardware counters are unavailable without root, so an A/B nightly could only be judged by
   end-to-end cells — a high-variance, low-signal experiment for a toolchain that is not implicated.
3. v2 itself says a nightly failure must not block the working stack; an install is a user-space but
   multi-GB, multi-hour operation that displaces the actual optimization work.

**Reopen triggers:** (a) the V01 discriminator shows a codegen-shaped cause (spills/occupancy that a
newer compiler could remove), (b) a specific upstream fix is identified for a path we execute and
pinned to a commit, or (c) the projection experiment lands and the next bottleneck is compiler-side.
If reopened: install beside the current SDK (never replacing it), pin URL+checksum+manifest, keep
both build dirs, and run the unchanged-source baseline + one candidate build.
